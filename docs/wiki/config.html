    Готовые конфиги

    Слить с существующим, не перезаписывать: сейчас в файле уже есть modelRoles.default, тема, composer и defaultThinkingLevel.

    Перед правкой cp ~/.omp/agent/config.yml ~/.omp/agent/config.yml.bak. Массивы в YAML заменяются, а не сливаются; проектный bash.patterns добавляется в начало, а не затирает глобальные.

    mcp.json

    Только если реально нужны Postgres или свежие доки библиотек. Глобальный файл — общий для всех worktree Orca.

    {
  "$schema": "https://raw.githubusercontent.com/can1357/oh-my-pi/main/packages/coding-agent/src/config/mcp-schema.json",
  "mcpServers": {
    "context7": {
      "type": "http",
      "url": "https://mcp.context7.com/mcp",
      "headers": { "Authorization": "Bearer ${CONTEXT7_API_KEY}" }
    },
    "postgres": {
      "type": "stdio",
      "command": "uvx",
      "args": ["postgres-mcp", "--access-mode=restricted"],
      "env": { "DATABASE_URI": "DATABASE_URI" },
      "timeout": 120000,
      "instructions": false
    }
  },
  "disabledServers": ["filesystem", "memory", "sequential-thinking", "fetch", "playwright"]
}
    Секреты "DATABASE_URI": "DATABASE_URI" — голое имя переменной: OMP возьмёт значение из окружения (файл .env подхватывается, если вы его создали). Ключа в самом mcp.json нет. auth.type: "apikey" ничего не подставляет. Поле cwd в примере опущено: для сервера, не зависящего от проекта, задайте его равным домашнему каталогу.

    Ключи, которые важны

    КлючДефолтСтавитьПочему
    tools.approvalModeyolowriteСпрашивает shell; в yolo критичные паттерны игнорируются
    tools.restrictedFolders[]списокСпрашивает всегда, включая yolo; матчит cwd для bash
    tools.approval.bash—не задаватьHeadless-сабагенты не могут ответить → отказ
    bash.patterns[]deny/promptНе покрывает eval; это policy, не sandbox
    providers.webKeylesstruefalseИначе keyless Parallel для web_search
    modelRoles.smol= defaultдешёваяИначе «дешёвый воркер» идёт на дорогой модели
    task.maxConcurrency326 / 10–128 ядер / 16 ядер; сабагенты ждут API, не CPU
    task.workerThreads40Воркеры включаются только при ≥9 одновременных
    isolation.backendautorcopyext4: reflink/btrfs недоступны, overlay не смонтирован
    worktree.clonetruefalseНа ext4 это полная копия, а не CoW
    lsp.formatOnWritefalsefalseИначе массовый reformat при каждом write
    lsp.enabledtruetruefalse не отключает LSP из write/edit
    mcp.startupTimeoutMs2501000Холодный npx/uvx не успевает
    tui.mousefalsefalseИначе колесо не скроллит
    display.showTokenUsagefalsetrueКонтроль расхода на каждом ходе
    composer.predictionstruefalseЛишний запрос модели на каждый ход

    Чего не делать

    Не делатьЧто произойдёт
    tools.approval.bash: prompt глобальноКаждый сабагент с bash получит отказ вместо вопроса
    isolation.backend: reflinkext4 не умеет FICLONE → фолбэк и лишние попытки
    lsp.formatOnWrite: trueГигантские диффы, конфликты со стилем репозитория
    tui.mouse: trueКолесо перестаёт скроллить, выделение только Shift+drag
    compaction.strategyКлюча нет (советы блогов под omp 16.x)
    shellCommandPrefix как env-обёрткаНативный шелл его игнорирует
    modelRoles.judge без нативного бэкендаprewalk.auto, autoParallel, find молча не работают
    Проектный .omp/config.yml вне gitНовый worktree Orca его не увидит
    symbolPreset: nerd без Nerd Font«Тофу» вместо иконок; авто-апгрейд не откатит
    Запуск из подкаталогаПроектные настройки не применятся

    Порядок применения

    1. Бэкап и tools + bash (безопасность) — проверить новой сессией.
    2. secrets, providers — перезапуск не нужен, читается на старте.
    3. modelRoles + retry — сверить через /model → Roles.
    4. task, isolation, worktree — проверить одним тестовым фан-аутом.
    5. lsp, display, composer, mcp — по вкусу.
