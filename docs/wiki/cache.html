    Кэш префикса: как не долбить провайдера

    Что именно кэшируется, что ломает кэш гарантированно, а что безопасно. Замеры — на этой машине, OMP 19.1.0, модель cline-pass/deepseek-v4.1-flash-1017.

    Три ответа Спавн сабагента не ломает кэш родителя — это отдельная сессия. Смена режима, модели, thinking level или tool-set — ломает. Дороже всего не TTL, а мелкие мутации середины: поздний MCP, compaction, retry на другую модель.

    Что входит в префикс

    СлойВ префиксеКомментарий
    System promptдаblock 0 + один trailing <project-context>. Anthropic-breakpoint стоит до него, поэтому разные cwd делят статическую часть
    Tool schemasдапорядок и описания тулов — часть байтов; inlineToolDescriptors переносит описания в промпт
    Messagesдаappend-only лог; compaction заменяет голову истории
    Модель / thinking / retentionnamespaceпровайдерский cache key: смена = другой кэш, даже при том же тексте

    Источники: omp://system-prompt-customization.md:18, cfg://provider.appendOnlyContext.

    Ломает гарантированно

    ДействиеПочему
    /modelдругая модель = другой кэш; плюс имя модели в system prompt при includeModelInPrompt: true
    Thinking level (/effort, Shift+Tab)явно в списке причин miss; Responses сбрасывает chain при смене options
    Вход/выход plan modeменяются tools + model/plan-контекст
    Vibe modetool-set сокращается до vibe_*
    goal create / goal dropдобавляется/удаляется goal-тул
    prewalk handoffсмена модели на первом edit
    Compactionновая голова контекста
    MCP add/remove//mcp reloadменяются схемы тулов и instructions
    Установка/скрытие скилламеняется каталог скиллов в system prompt
    /clear, /new, смена профиляротация provider state / изолированные кэши
    Retry-fallback на другую модельтихо уводит запрос в чужой namespace

    Список причин miss: omp://settings.md:978; tool-set и model — omp://compaction.md, omp://provider-quirks.md.

    Что не ломает

    • Новые сообщения, tool results, async-результаты, advisor-notes, goal-continuation — это append.
    • Спавн task-сабагентов и write agent://<id>: у ребёнка своя история, родительский префикс не трогается.
    • /skill:<name> и read skill:// — тело приходит сообщением, промпт не меняется.
    • chillax посреди хода — документировано как «without invalidating the prompt cache».
    • Смена approval mode — локальный гейт, не часть запроса.
    • Переключение терминала/вкладки в Orca — разные процессы, на кэш не влияет.

    Конфиг

    provider:
  appendOnlyContext: auto

providers:
  cacheRetention: auto        # long — только если паузы >5 мин и провайдер даёт 1h
  cacheWarming: idle          # off для one-shot/CI
  cacheWarmingStrategy: auto

display:
  cacheMissMarker: true
  showTokenUsage: true

mcp:
  startupTimeoutMs: 0         # все серверы до первого хода; 2000 — компромисс

retry:
  modelFallback: true
  fallbackOn: usage-limit

compaction:
  methodOrder: [remote, handoff, snapcompact, shake, soft]
  midTurnEnabled: true        # false — только если cache важнее риска overflow

advisor:
  enabled: false

prewalk:
  enabled: false

    Если видите промахи «на ровном месте» — запините defaultThinkingLevel (high): классификатор auto может менять effort между ходами.

    Как мерить

    Read-only по JSONL сессий; то же считает omp stats, но без записи stats.db.

    cd ~/.omp/agent/sessions/<project> && python3 - <<'PY'
import json, glob
for f in glob.glob('**/*.jsonl', recursive=True):
    i=r=n=0
    for line in open(f, encoding='utf-8', errors='replace'):
        try: u=(json.loads(line).get('message') or {}).get('usage')
        except: continue
        if not u: continue
        i+=u.get('input',0); r+=u.get('cacheRead',0); n+=1
    if n: print(f"{100*r/(i+r):5.1f}%  {n:3d}t  {f[-40:]}")
PY

    omp stats --json даёт cacheRate и разбивку byAgentType (main/subagent/advisor), но сначала синхронизирует сессии в ~/.omp/stats.db — это уже запись.

    Что вы приобретаете, ломая кэш

    ПоломкаВыигрышКогда оправдано
    Смена моделикачество на сложном участкезадача длинная, ошибка дороже одного prefill
    prewalkсильный план + дешёвое исполнениедолгая реализация после плана
    Advisorвторое мнение, ловит пропущенноерискованные изменения, финал перед PR
    Compactionпродолжение за пределом окнатолько когда реально упёрлись в контекст
    Сабагентыизоляция и параллельностьпочти всегда: цена — один холодный ход ~4–9k

    Правило: ломать кэш можно, но осознанно — на границе задачи, а не посреди неё. Когда лимитов с запасом, холодные старты перестают быть проблемой денег и остаются проблемой времени (TTFT), поэтому дисциплину префикса держим ради latency.

    Оговорки

    • Для cline-pass в доках не подтверждены ни cacheRetention, ни shared-prompt-cache, ни TTL. Факт кэша виден только по cacheRead в usage.
    • Общий кэш между сабагентом и родителем возможен только на моделях с shared-prompt-cache; для текущей модели это не подтверждено.
    • Порог, по которому cacheMissMarker решает, что запрос «потерял» кэш, в доках не описан.
    • Влияние thinking/effort на кэш у Anthropic/OpenAI официально не подтверждено; OMP относит смену thinking к причинам miss.
