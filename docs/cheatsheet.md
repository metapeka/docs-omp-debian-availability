# Шпаргалка: режимы, мониторинг, диагностика

Онлайн: https://metapeka.github.io/docs-omp-debian-availability/wiki/guide.html

Коротко: как запускать, что означает каждая цифра, что делать, когда что-то
пошло не так. Полный план и замеры — `docs/plan-cache-modes.md`, вики —
`docs/wiki/cache.html`.

## 1. Запуск: какой режим

| Хочу | Команда | Кэш |
|---|---|---|
| обычная работа | `omp-mode cache-safe` | самый стабильный префикс |
| сложная задача, план/ревью на сильной модели | `omp-mode quality` | ломается на переходах plan/advisor |
| времени важнее, лимитов с запасом | `omp-mode throughput` | та же дисциплина, но больше параллелизма |
| без пресета | `omp` | глобальный `config.yml` |

Режим выбирается **до** первого сообщения. Посреди сессии режим не
переключается — это и есть холодный префикс. Продолжить прошлую сессию в
выбранном режиме: `omp-mode cache-safe --continue` (или `--resume`).

## 2. Что на экране

Правая часть статус-строки:

| Сегмент | Пример | Смысл |
|---|---|---|
| `status` | `cache-safe ↺ 98%` | режим + hit rate последнего запроса |
| `token_total` | `12.4k` | токены текущего контекста |
| `cost` | `$0.0042` | стоимость сессии |
| `context_pct` | `12%` | заполнение окна |

`↺ N%` — доля кэша в промпте: `cacheRead / (input + cacheRead)`. Высокий
процент = дешево. `↺ …` — ходов ещё не было.

## 3. Команда `/cache`

Печатает одной строкой:

```
режим: cache-safe · cline-pass/deepseek-v4.1-flash-1017 · thinking high ·
ход: ↺ 98% · in 51 · cached 2560 · $0.0000 ·
сессия: $0.0000, ходов 1, ↺ 98%
```

| Поле | Откуда | Что значит |
|---|---|---|
| режим | `OMP_MODE` от `omp-mode` | какой пресет загружен; `без пресета` — запуск голым `omp` |
| модель | активная модель | |
| thinking | эффективная настройка | у моделей с уровнями `off\|auto` это `auto`, разрешённый уровень скрыт |
| ход: ↺ / in / cached / $ | `turn_end.message.usage` | последний запрос: hit, некэшированный input, из кэша, стоимость |
| сессия: $ / ходов / ↺ | накопление расширения | сумма и средний hit по сессии |

Предупреждение «Кэш префикса: hit N%» приходит, когда hit < 50% на ходе не
первом и промпт ≥ 4000 токенов. Это не ошибка сама по себе — сигнал, что
префикс сменился.

## 4. Переключения и их цена

| Действие | Как | Что с кэшем |
|---|---|---|
| сменить модель | `/model:cline-pass/deepseek-v4-pro` | возможно промах, **не гарантирован** (у новой модели может быть свой кэш) |
| сменить thinking | `/effort <уровень>` | меняет namespace; у `off\|auto`-моделей выбора почти нет |
| войти/выйти из plan | `--plan-yolo` при запуске | новые tools и model → промах |
| MCP, скиллы | до старта сессии | поздняя регистрация — промах |
| продолжить сессию | `--continue`, `--resume` | история и кэш-ключ восстанавливаются |
| начать заново | `/new` | новый namespace, всё холодное |

Правило: ломать кэш можно, но на границе задачи, а не посреди неё.

## 5. Диагностика: симптом → что делать

| Симптом | Сначала | Потом |
|---|---|---|
| «дорого» | `/cache`: стоимость хода и сессии | `omp stats --json` — общая картина |
| «кэш не работает» | `↺` в статусе и в `/cache` | `stats` → `overall.cacheRate` |
| пришло предупреждение о промахе | что менял за 1–2 хода до этого | `↺` следующего хода: вернулся ли |
| `/cache` пишет «неизвестная команда» | расширение не загрузилось | проверить `~/.omp/agent/extensions/cache-monitor.ts`, запустить `omp` и посмотреть stderr |
| режим не тот | строка `status` и `/cache` | `PI_CONFIG_FILES=… omp config list` — какие значения реально склеились |
| «кто тратит: я или сабагенты» | `stats` → `byAgentType` | `byModel` — какая модель |
| пресет «не работает» | `PI_CONFIG_FILES=<preset> omp config list` | значение вне enum OMP игнорирует молча |

## 6. Готовые команды

```bash
# сколько стоил весь период и какой был кэш
omp stats --json | jq '.overall | {totalCost, totalRequests, cacheRate, cacheSavings}'

# по агентам: main vs subagent
omp stats --json | jq -r '.byAgentType[] | [.agentType, .totalRequests, .totalCost] | @tsv'

# по моделям
omp stats --json | jq -r '.byModel[] | [.model, .totalRequests, .totalCost] | @tsv'

# цены модели (input / output / cacheRead за 1M)
omp models --json | jq -r '.models[] | select(.id|test("deepseek")) | [.id,.cost.input,.cost.output,.cost.cacheRead] | @tsv'

# проверить, что пресет реально применяется
PI_CONFIG_FILES=$HOME/.omp/presets/throughput.yml omp config list | grep -E 'maxConcurrency|advisor.enabled'

# hit rate по каждой сессии (read-only, без stats.db) — скрипт из docs/wiki/cache.html
```

`omp stats` синхронизирует `~/.omp/stats.db` (это запись). Скрипт по JSONL
сессий — только чтение.

## 7. Пример чтения (эта машина, 2026-11-22)

| Метрика | Значение |
|---|---|
| запросов | 706 |
| стоимость | $1.95 |
| `cacheRate` | 98.2% |
| `cacheSavings` | 96.2% |
| cacheRead | 104.7M токенов |
| main | 386 запросов, $1.02 |
| subagent | 254 запроса, $0.83 |

Вывод: сабагенты — почти половина счёта при 254 запросах; кэш экономит ~96%
от цены без кэша.

## 8. Пять правил

1. Режим и модель — до первого сообщения, не посреди задачи.
2. Менять модель только на границе задачи и смотреть `↺` после.
3. MCP и скиллы — до старта.
4. Продолжение — `--continue`/`--resume`, не `/new`.
5. Раз в неделю смотреть `stats`: без числа «стало лучше» не отличить от «стало дороже».
